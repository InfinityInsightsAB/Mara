# Rules for the Numerical-Results Workflow

This file is the living instruction sheet for all future work on the numerical-results part of the manuscript. It must be updated whenever the workflow, scope, or publication standard changes. Future agents should read it before starting work.

## Writable Work Areas

Only the following two folders are writable for this manuscript workflow:

- `C:\MDU PhD\Paper C\Working Files\Manuscript Overleaf`
- `C:\MDU PhD\Paper C\Working Files\Manuscript Code`

No future agent should modify other folders for this manuscript workflow unless the user explicitly expands the scope.

## Canonical Locations

The canonical manuscript source is:

- `C:\MDU PhD\Paper C\Working Files\Manuscript Overleaf`

The canonical manuscript-code and reproducibility source is:

- `C:\MDU PhD\Paper C\Working Files\Manuscript Code`

All manuscript-facing figures, table snippets, and other Overleaf assets must ultimately live inside `Manuscript Overleaf`.

Every future manuscript revision must be rendered from `Manuscript Overleaf`.

## Current Scientific Scope

The current work concerns only the numerical-results program for the paper.

- Theoretical sections are not to be rewritten during the present numerical-results phase.
- The theory may be referenced when explaining the experiments, but the current task is numerical assembly and numerical exposition.
- The focus is the numerical behavior of LSMC and Hybrid LSMC-PDE under the calibrated gDMR setting.

All future numerical writing must be scientific-paper quality, mathematically explicit, and suitable for a PhD-level mathematics article.

## Benchmark Policy

The canonical benchmark for manuscript comparisons is plain LSMC with:

- `1200` Euler steps
- `1,200,000` paths
- `95%` confidence intervals

Benchmark values are the manuscript reference values against which relative errors are to be reported.

## Reporting Policy

The manuscript reports direct prices only.

- Hybrid results reported in the paper are hybrid direct prices.
- LSMC benchmark references are benchmark direct prices.
- Confidence-interval information is mandatory in numerical reporting.
- Relative-error figures must display confidence-interval information.
- Tables must include at least direct price, standard error, and a confidence-interval quantity or bounds.

If low-estimator values are encountered in source material, they may be used for internal context, but they are not part of the manuscript-facing reporting target for the current paper.

## Reuse Policy

Reuse of saved results is preferred whenever the saved material is valid, traceable, and aligned with the locked manuscript standard.

In particular, future work should first look for reusable material in:

- `C:\MDU PhD\Paper C\Experiments 26.03`
- `C:\MDU PhD\Paper C\Working Files\Final Code`

However, no manuscript-facing value should be cited from an external folder without being copied into `Manuscript Code` and logged in `PROVENANCE.md`.

If a required value is missing from active reference sources, it should be marked as a later recomputation target rather than guessed or reconstructed from incomplete evidence.

## Figure Standard

All figures must share a single professional publication style.

This means future figure work must enforce consistency in:

- font family
- color palette
- line widths
- marker sizes
- panel layout
- caption style
- filename grammar
- axis labeling

Every manuscript-facing figure must be generated by Python code stored in `Manuscript Code`.

- Stored data may be reused, but the final figure must still be regenerated by a standalone Python script.
- The Python script is the source of truth for the figure, not a hand-authored LaTeX or TikZ figure file.
- Overleaf must include exported figure assets only.
- Figure-generation scripts must export both `.pdf` and `.eps`.
- Figure provenance must record the Python script, the local input data files, the exported outputs, and the output checksums.

No absolute filesystem paths are allowed in manuscript-facing figure references, markdown summaries intended for manuscript use, or LaTeX figure includes.

## Writing Standard

The numerical section must match the formal register of the theoretical part of the manuscript.

- The prose must read as publishable mathematical writing, not as an internal progress note.
- Conversational framing is not allowed.
- First-person transitions such as `we now turn`, `we next`, or `to make this concrete` are not allowed.
- Summary language such as `taken together`, `the message is`, or similar commentary-style wrap-up phrases is not allowed.
- Claims must be tied to tables, figures, definitions, and measurable numerical properties.
- Interpretations must remain restrained and evidence-led.

The intended prose model is a formal research article in applied probability, stochastic analysis, or quantitative finance.

## Code Standard for `Manuscript Code`

Any future code written in `Manuscript Code` must satisfy all of the following:

- standalone
- simple to run
- reproducible
- manuscript-specific
- self-contained in its folder logic whenever local stored inputs are already available
- free of code comments

Heavy pricing simulations remain outside the present manuscript-assembly phase.

Lightweight tasks are allowed when they use stored data only, including:

- copying reusable saved inputs into `Manuscript Code`
- normalizing stored numerical results
- generating tables from stored data
- generating publication figures from stored data
- exporting Overleaf-facing assets
