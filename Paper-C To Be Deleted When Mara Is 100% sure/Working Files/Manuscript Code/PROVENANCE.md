# Provenance and Reuse Policy

This file defines how reused numerical material is to be documented before it becomes part of the manuscript-specific workflow.

The current manuscript phase permits the copying of saved numerical inputs, the local computation of missing manuscript source tables when the saved bundle is incomplete, the generation of tables from those inputs, and the regeneration of publication figures from those inputs by manuscript-specific Python code.

## Why This File Exists

The project already contains saved benchmarks, summaries, tables, and renderers in active folders outside `Manuscript Code`. Those materials are valuable, but they must not remain informal external references once the manuscript package is assembled.

Before any reused number, table, or figure enters the manuscript-facing workflow, it must be:

1. located in an active reference source
2. copied into `Manuscript Code`
3. described in this file
4. represented in a machine-readable manifest if generated by a helper script

## Required Provenance Format

Every reused item must be documented using the following fields:

- `Original project path`
- `Copied manuscript-code path`
- `Scenario or strike`
- `Numerical settings`
- `Study type`
- `Reuse mode`
- `Notes`
- `Checksum source`

Each manuscript-facing figure must also record:

- `Python script path`
- `Local input data files`
- `Exported figure files`
- `Output checksum`
- `Export formats`

## Field Meanings

- `Original project path`
  - the exact source path in the broader project
- `Copied manuscript-code path`
  - the destination path inside `Manuscript Code`
- `Scenario or strike`
  - for example `ATM`, `OTM put`, `K=80 put`, `K=70 put`, or a five-strike combined study
- `Numerical settings`
  - benchmark steps, paths, seeds if relevant, and any other configuration needed to identify the result
- `Study type`
  - one of `benchmark`, `step sweep`, `path sweep`, `renderer`, `summary`, `table`, `figure`, or another explicit category
- `Reuse mode`
  - either `reused directly` or `rebased`
- `Notes`
  - short explanation of why the item is being reused and any caution about its interpretation
- `Checksum source`
  - either the sha256 stored directly here or the manifest file in which the checksum is recorded
- `Python script path`
  - the manuscript-specific Python script that regenerates the figure
- `Local input data files`
  - the local stored CSV or table files consumed by that script
- `Exported figure files`
  - the `.pdf` and `.eps` outputs used by the manuscript workflow
- `Output checksum`
  - the sha256 values of those exported figure files
- `Export formats`
  - currently `.pdf` and `.eps`

## Reuse Standard

Reuse is preferred over recomputation whenever the existing saved material is:

- in an active reference source
- aligned with the locked manuscript design
- clearly traceable
- suitable for direct or rebased manuscript use

If the saved material does not meet those criteria, it should be marked as a later recomputation target instead.
